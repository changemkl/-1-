# 战客一组· 三棵树经营工作台

面向客户经理的客户组织树、产业链树、产品与场景树工作台。腾讯文档维护客户名称、稳定编号和客户分类，独立画像库维护采集内容；当前页面展示已接入的资料，不展示示例客户或口号。网页展示无需密钥；后台同步凭据通过 GitHub Secrets 提供。

使用 Node.js 18 或以上版本，在仓库目录运行 `npm run dev`，默认端口为 3000，可通过 `PORT` 调整。无需安装 npm 依赖。运行 `npm run check` 检查 JavaScript 语法。

开发模式会检测 HTML、CSS 和 JavaScript 文件变化，并在约一秒内自动刷新打开的页面。云端使用平台的 3000 端口预览入口访问；本机运行时访问 localhost:3000。`npm start` 启动不含自动刷新的普通服务。

采用蓝色数据总览、横向导航和客户卡片布局，支持三视图切换、板块和等级组合筛选、实时搜索、画像展开及筛选结果 JSON 导出。统计值根据已接入的业务资料计算；无数据栏目显示为空。页面使用系统字体，不需要访问外部字体服务。

## 腾讯文档自动同步

官方接口：`/openapi/drive/v2/util/converter` 转换链接 ID；`/openapi/spreadsheet/v3/files/{fileId}/{sheetId}/{range}` 读取内容。数据源固定为用户提供的公开表格 `DTEhRanNnS3dJV2hm`，子表 `BB08J2`，按子表实际尺寸读取，最多 6000 行、200 列（超过时任务失败并保留旧文件）。首次调用需要文档 ID 转换权限，读取需要 `scope.sheet.readonly` 或对应读写权限。

在 GitHub Actions Secrets 中保存 `TENCENT_DOCS_CLIENT_ID`、`TENCENT_DOCS_ACCESS_TOKEN`、`TENCENT_DOCS_OPEN_ID`。不把凭据保存进代码、JSON 或日志。Token 到期后更新 Secret；当前没有配置自动续期。

建议 Settings → Pages → Source 选择 **GitHub Actions**；首次部署已在当前设置下验证成功。工作流 `Sync Tencent spreadsheet` 每小时第 17 分钟运行（GitHub 可能延迟），也可以在 Actions 中手动 Run workflow。计划任务读取默认分支的工作流，所以默认分支也需要保留此工作流文件；任务固定检出并更新 `customer-workspace`。成功读取后提交公开数据 `public/tencent-data.json`，并使用 Pages 官方部署步骤发布根入口和 `public` 子目录，避免机器人提交不触发 Pages 构建的问题。没有数据变化时不重复提交，但仍部署最新页面。首次同步必须成功后才能看到真实数据。

网页每分钟检查已经发布的 JSON；这不会消耗腾讯 API 额度。腾讯 API 调用由工作流产生，每次需要多页时调用数会增加；不要将 20000 次试用额度理解为每月重置。失败时保留上一次成功数据，并在 Actions 中显示失败，页面显示的是最近数据变更时间，不声称后台最近检查成功。

腾讯表格按每行一个客户读取，客户名称和集团编号用于关联，客户类别／行业分类及客户标签用于展示。客户明细原表不在网页展开。基础列之外新增的列单独同步为工作日志；表格数据会作为公开 JSON 发布，请只填写允许公开的内容。

验证：`npm run check`；`python3 -m unittest discover -s tests -v`。这些验证不等于真实 API 和线上部署成功，需要查看首次 Actions 结果。


## 独立画像数据库与采集

腾讯文档维护客户名称、集团编号与分类。采集任务使用临时 SQLite，跨次保留的数据发布在独立的 `public/profile-data.json` 中，随 GitHub 提交保留版本。当前无需 Cloudflare；D1 / Workers 是尚未部署的可选方案。

GitHub Actions 每小时检查已配置的官方来源，发布快照并部署网页；来源不可访问时保留此前可核验记录。这是定时更新，不是全网实时搜索。新增客户还需要在 `intelligence/sources.json` 配置其官方来源。



## 当前只读展示版本

客户名称位于 public/tencent-data.json；官网采集内容独立位于 public/profile-data.json。网页展示信息化项目与采购、官网领导分工、原文链接及采集时间，暂不提供编辑、审核、跟进等业务交互。无需配置 Cloudflare。Collect customer intelligence 工作流每小时更新采集快照并部署网站；来源失败时保留此前资料。采集说明见 intelligence/README.md。

## 公开事实展示标准

仅展示官方 HTTPS 来源中可核验的信息化建设记录，以及官网领导页面明确列示的姓名、职务、分工。普通会议、体育活动、土建总投资不作为信息化商机；会议出席名单不作为现任领导依据。

项目分别标注采购意向、采购公告、中标/合同、规划或公开建设动态。金额与截止日期必须有明确原文字段；总投资不转为信息化预算，中标金额不转为采购预算。客户是供应商或其他单位才是采购人时单独说明，不认定为客户采购需求。未知字段留空；历史公告不自动视为仍在招标。

当前采集限于配置的单位官网及其栏目，不保证覆盖政府采购平台、动态加载页面或所有历史公告。领导信息表示采集时官网的列示，仍应查看原文及更新时间；采集时间不等于任职生效时间。

产业链树以中移动系统集成有限公司为我方单位，将当前客户组织树中已核实的中标供应商汇总为潜在合作伙伴，保留客户、标项与公告来源，按名称去重并排除我方公司。可手动添加、编辑、移除已合作伙伴，或将潜在伙伴添加为合作伙伴。手工名单保存在当前浏览器 localStorage，暂不跨设备共享，清理网站数据会删除该名单；不写入腾讯表格。

东风平台导入的合作伙伴快照保存在 `public/cooperation-partners.json`，所有浏览器可见；仅导出厂商名称、平台来源、业务方向与合作分类，区分平台登记的合作成果和合作意向，排除示例与未具备合作依据的生态记录。与公开中标供应商按已确认名称/别名去重。平台导入名单可以在当前浏览器编辑，但不提供本地删除系统名单的入口。手动添加和编辑仍保存在当前浏览器；此次导入不代表已建立私有平台定时同步，仓库不保存平台登录凭据、原始业务记录或联系人数据。

合作伙伴卡片以已核实的关联线索/商机名称及历史合作登记为主体，不把公开采购中标当成与我司合作。合作沟通与已完成合作分开标注；生态登记仅给出客户单位或成果描述时，标明未注明具体项目名称。没有明确名称关联的显示待核实，不按相同客户或行业推断合作关系。

工作日志不使用大模型：`public/worklog-config.json` 冻结首次真实读取时已有内容的基础列，`public/sheet-columns.json` 记录列名与非空行数，`public/worklogs.json` 保存其余列中每个非空单元格的原文和来源单元格。基础列不会自动增加；当前基础列为集团编号、客户名称、客户标签、一级属地、二级属地、客户类别，以及未命名的 G 列。建议在这些列右侧追加日志列，并用完整工作日期命名（如 `2026-10-26`）。没有日期的记录不填入今日日期；仅月日的记录明确标注年份推定。修改同一格更新原日志，清空单元格或删除客户行后，下一次同步不再展示相应记录；历史版本由 Git 保留。

“读取工作日志”进入 `read-worklogs.yml` 的 GitHub Actions 页面，使用有仓库权限的账号点击 Run workflow 即可读取并发布日志，不改客户名单。“同步在线表格”进入 `sync-tencent.yml`，更新客户名单与日志，并在手动运行时触发客户公开资料补充；新增行中的客户名称生成新卡片，新增列不被当作客户。网站会监测手动任务状态并刷新结果，也可点击“读取已发布结果”。GitHub Pages 没有保密的后台任务触发接口，因此按钮不会在未经 GitHub 身份验证的情况下直接发起 workflow dispatch；没有在浏览器保存腾讯或 GitHub 密钥。五分钟定时同步继续在后台运行。

方案 5 的独立同步接口已提供于 `sync-service/`，部署步骤见该目录 README。实际服务部署后，将 `public/sync-config.json` 的 `apiBaseUrl` 配置为接口 HTTPS 根地址，网页自动切换为直接提交、查询同步任务，不再打开 GitHub。当前地址为空，表示尚未部署和启用；现有入口保留。接口所需 GitHub token 保存在服务端，网页只接收短期同步授权。

客户组织树保留客户卡片。点击卡片空白处、客户名称或“查看三棵树”打开该客户的侧栏，切换组织树、产业链树、产品与场景树；原采购、历史结果、日志快捷入口仍可单独打开。产业链只按当前客户的公开中标来源建立供应商关系，再标注其中的我司合作伙伴，不将全局合作名单直接分配给每个客户。`public/customer-scenes.json` 用于经过核实的客户场景与产品关系，记录需匹配 `customerId` 和 `customerName`，场景及产品分别提供 HTTPS 来源链接；目前未填入示例场景，采购原文只作为公开需求线索展示。

客户卡片仅展示名称、标签、主要职能及资料覆盖标记，不放功能按钮。点击卡片进入统一客户详情侧栏：一级为三棵树／工作日志／采购信息；三棵树内切换组织、产业链、产品场景，采购信息内切换采购意向与招标、历史招标结果。客户编号、地址、来源链接和竞争对手 TOP3 等内容保留在详情中，各模块复用同一侧栏，不弹出第二层客户窗口。
